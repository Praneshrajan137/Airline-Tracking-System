## Corrected or removed claims

- “Production ready” was removed from the README and completion status. Current deployment and operational evidence does not support it.
- “Real-time” and “live position” were replaced with “reported status,” source timestamps, and last-position age because provider freshness is not guaranteed.
- Unsupported claims such as 31 ms latency, 99.9% uptime, 100 concurrent users, 90% coverage, and a specific monthly API cost were removed from current product copy.
- The default summary model was changed to `gpt-6-luna`; the [OpenAI API model/pricing page](https://platform.openai.com/pricing) lists it, but this account's access and a real provider request remain unverified.
- OpenAI calls are limited by global Redis counters in configured minute/hour/day windows. Redis failure rejects a provider request; the counters do not guarantee a billing amount.
- The summary service declares only the `.DLT` topic; the producer or Kafka operator owns the source topic. Managed Kafka must set DLT partitions to at least the existing source partition count; actual provisioning and DLT send behavior still require a broker-backed run.
- Authentication was removed from the traveler flow and the gateway denies account routes; account support is deferred.
